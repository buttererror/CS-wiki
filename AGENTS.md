# Repository Agent Guidelines

## Reality-First Knowledge Organization

Organize this wiki according to real disciplinary and conceptual relationships.
Do not force a concept into an existing directory merely because that placement
is convenient for the current repository structure.

When reviewing or adding a concept:

1. Determine its most accurate field, scope, and abstraction level before
   choosing a file location.
2. Make the repository reflect that conceptual model. Propose a new scope,
   distinction, landing page, or directory when the existing structure is
   insufficient.
3. Separate conceptual classification from repository placement. A directory
   is a navigation and ownership choice, not proof of strict academic
   containment.
4. Distinguish foundational fields from applied engineering practices.
5. Describe overlapping or many-to-many relationships as relationships, not as
   rigid parent-child hierarchies.
6. Distinguish temporary organization from the intended long-term taxonomy.
   In particular, `miscellaneous/` is a review inbox, not a subject category.
7. Prefer one canonical explanation of a concept and connect other relevant
   areas with cross-links instead of duplicating definitions.

Taxonomy diagrams are orientation tools. Treat them as realistic but revisable
models rather than exhaustive ontologies or mandatory implementation sequences.

When proposing placement for a new concept, explain:

- its conceptual classification;
- the disciplines and scopes it relates to;
- its recommended canonical file location;
- which landing pages should link to it; and
- any important corrections or qualifications needed in the source material.

## Engineering English

When useful, briefly suggest the correct engineering terminology and correct up
to three important English issues in the user's message. Prioritize the
engineering task and avoid full English lessons unless explicitly requested.
